## 排查记录：text_00_0-01.pac「修改不生效」怪象（2026-10-18）— ✅ 已破案

**现象**：用户修改/替换 `text_00_0-01.pac` 后游戏内开场白不变；其它 text pac 修改生效、替换变空（正常）；删除 01.pac 报错。

**结论（procmon + 图像解码双重实锤）**：**预渲染文字图机制**。开场白的 message key
（`00_0-01_01_001` 等）在 `data\story\image\` 目录有**同名文件**（如 `00_0-0-01_01_001.hip`），
是制作时把台词渲染成的美术字图片（中央描边大字+ruby 注音样式）。运行时**优先用图片，atf 文本被忽略**：
- 改 atf / 替换 pac 无效（显示的是图片像素，文本源不在 pac 内）
- 全域文本搜索找不到「第二份」（它是像素不是字节）
- 删除 pac 崩溃（AdvCtrTask 挂载流程性检查文件存在，但内容不用于显示）
- **消息无同名 hip 时回退 atf+font 实时渲染**（00_0-01_01_005 起无图 → 正常对话改 atf 生效）

procmon 证据（事件 11:18:03）：01.pac 被整体 ReadFile（362,608 字节，游戏确实读了修改后的文件），
同瞬间 `data\story\image\00_0-01_01_00{1,2,3,4}.hip` 被逐个 ReadFile——显示的是它们。

图像验证（`scratch/decode-tga.fsx` → 将移入 scripts/）：image 目录的 .hip 实为 **TGA type9**
（RLE 压缩 256 色索引 + 32bit BGRA 调色板 + 标准 TGA footer 签名 "TRUEVISION-XFILE"）。
`00_0-01_01_001.hip` = 1024×128，解码出「影を生み出す月灯り」+ ruby「つきあか」，
与游戏截图逐像素吻合。GeoArcSysAIOCLITool 不认此变体（hipster.exe 可解但无源码）。

## 标题菜单绘制逻辑（2026-10-19 IDA 逆向 ✅）

**结论先行**：菜单项位置来自**写死的坐标表**，绘制时**缩放恒为 1.0（原尺寸 1:1 绘制）**。
所以屏幕位置 = 绘制坐标 + **图片内文字的像素位置**。

### 关键函数

| 地址 | 作用 |
|------|------|
| `sub_53B400` | 标题菜单绘制主函数（含 18 项循环） |
| `sub_53B6C0` | 同类绘制函数（另一处引用同一名称表） |
| `sub_5680C0(name, v5, 0)` | 按资源名加载（`off_11DC118[i]` = `title_menu_00`…） |
| `sub_5073B0` | 实际绘制调用 |
| `off_11DC118` | 资源名字符串表（`title_menu_00` 起） |
| `dword_11A3520` / `dword_11A3524` | **坐标表**（相差 4 字节，X/Y 交错存） |

### 绘制调用签名（Hex-Rays）

```c
sub_5073B0(资源句柄,
    (float)dword_11A3520[7 * i],   // X
    (float)dword_11A3524[7 * i],   // Y
    0, v6[i + 50], 1, 128, 0,
    1065353216, 1065353216,        // 1.0f, 1.0f ← 缩放恒 1.0
    0, 1, 0, 0, -1, -1, -1)
```

⚠️ `(float)dword[...]` 是**整数转 float**（不是位模式重解释），所以表里存的是整数坐标。

### 对汉化的硬约束（血泪总结）

1. **画布尺寸绝对不能改** —— 绘制缩放恒 1.0，画布尺寸就是屏幕占位。
2. **文字在图片内的像素位置必须与原图一致** —— 曾试过「居中 / 统一绝对像素 / 按画布比例」三种
   策略，全部导致错位或字号不一。正确做法是直接复刻原图墨迹的 **左上角坐标 + 高度**。
3. **原图的字高本来就不统一**（`_01`=34 / `_02`=37 / `_04`=35 / `_05`=31 / `_06~09`=33），
   这不是 bug，是原美术设计。照抄即可。
4. 宽度不够（中文方块字比日文假名宽）时**横向压缩**，以左边缘为基准，字高不变。

### 定位方式：`a7 = 0`，引擎**不做**居中补偿（2026-10-19 二次逆向，**推翻**下面的旧结论 ⚠️→✅）

> ❌ **旧结论（已作废）**：`a7 = 128 非零 → x -= 宽×0.5 → X/Y 是图片中心`。
> 作废原因：**Hex-Rays 参数错位**。`sub_5073B0` 的 `a4` 是 `__int64`（占两个栈槽），
> 而调用点经函数指针强转、按 **17 个 4 字节参数**压栈（`add esp, 44h` = 17 槽已证）。
> Hex-Rays 仍显示 16 个形参却列 17 个实参文本，照抄文本映射会整体错一位，
> 于是把 `a6`(128) 当成了 `a7`、把 `a8`(1.0f) 当成了 `a9` —— 得出「a7=128 居中、a8=0」。

**按汇编逐条 push 还原**（`sub_53B400` else 分支 `loc_53B562`，cdecl 从右往左）：

| push 序 | 值 | 形参 |
|---|---|---|
| 1–3 | -1, -1, -1 | a16, a15, a14 |
| 4 | 0 | a13 |
| 5 | 0（if 分支是 1） | a12 |
| 6 | 1 | a11 |
| 7 | 0 | a10 |
| 8–9 | `dword_5D7D10` = **1.0f** | a9, a8（缩放 X/Y） |
| 10 | **0** | **a7（居中标志）** |
| 11 | 0x80 | a6 = 128 |
| 12 | 1 | a5 |
| 13–14 | `v6[i+50]`, `dword_5D7D00`(=0) | a4（`__int64`，低/高半） |
| 15–17 | Y, X, 资源句柄 | a3, a2, a1 |

常量实测：`dword_5D7D10` = `0x3F800000` = 1.0f；`dword_5D7D00` = 0；`unk_11A3674` = 0x1E0 = 480。

⇒ **`if (a7)` 不成立**，`a2/a3` 原样进入 `sub_40DD80` 的矩形：`[a2, a2+v41] × [a3, a3+v39]`
（`v41 = 纹理宽 × a8`、`v39 = 纹理高 × a9`，即原尺寸 1:1）。
⇒ 缩放恒 1.0 这一点仍然成立；但 **X=512 / Y=320·400·480·560 的语义（左上角 or 画布中心）
取决于渲染命令 4107 的锚点参数**（`sub_40DD80` 把 `a6=128` 写进结构 `v27[5]`），尚未逆向到底。
