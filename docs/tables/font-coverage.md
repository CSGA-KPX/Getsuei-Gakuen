## 3. 两个硬约束

### 3.1 jpn_glyph 的装载缓冲 < 3.6 MB（✅ 已实锤，2026-10-19 IDA 复核）

**不是推测，是真实分配**。`sub_510050` 按语言槽 `operator new[]` 两块缓冲：

```c
if (i) { v8 = 300000; v7 = 1800000; }       // 第 2 槽：abc 300 KB / hip 1.8 MB
else   { v8 = 600000; v7 = 3600000; }       // 第 1 槽：abc 600 KB / hip 3.6 MB
sub_513520(i)[+160] = v8;  sub_513520(i)[+172] = v7;   // 上限字段
sub_513520(i)[+152] = new[](v8);  sub_513520(i)[+164] = new[](v7);   // 真缓冲
```

加载函数 `sub_510190` 读文件大小到 `+168`/`+156`，`filesize >= 上限` 报
`"Localize Image size over"`。⇒ **`jpn_glyph.hip` ≤ 3,600,000 字节、`.abc` ≤ 600,000 字节**。

- 当前 hip 2,625,689 → **余量 974,311 字节（951 KB）**；abc 291,206 → 余量 308,794。
- 追加 2952 汉字，按 12×39 Gray16（936 B 原始、压缩后 300–500 B）估 → **974 KB 只够约 2000–3000 字形**，
  处在临界点，**动手前必须先实测压缩率**。

### 3.2 Font00 图集只有 256×256 / 289 格 → ✅ 可自由放大（2026-10-19 IDA 复核）

- `sub_43F290`（`AA_CFont_Tool::SetFontData`）**只解析 abc 头**（LineHeight/EntryCount/GlyphCount/表指针），
  完全不读图集宽高。
- 图集宽高在 `sub_510660` 里从 HIP 纹理对象取（`+140`/`+144`），即**运行时读 HIP 文件头**。
- ver5 走 float UV（0..1 归一化），换大图集 UV 数值不变。
- `sub_504A10` 判定：`Font00.hip` 存在 → 走标准解析；不存在 → fallback 到系统字体工厂。**无尺寸断言**。

⇒ 换 **512²（289→1156 格）或 1024²（4624 格）** 逆向层面无障碍；配套只需把 `Font00.abc` 的
`EntryCount` 从 28450（U+6F22）提到 ≥ U+9FA5(40869) 并扩 Mappings（62,928 → 约 88 KB，
Font00.abc 无大小上限）。

### 6.2 实测证据（2026-10-20 冒烟）

### 6.5 ⚠️ mapping 是 **0-based 直接索引**（第二次实机踩坑）

第一版重建装机后，存档界面变成**彻底乱码**：`Page` 显示成 `Qbhf`（每个字符 +1）、
`1` 显示成 `.`、`セーブ` 显示成 `七—ブ` —— **整体偏移一位**的典型症状。

原因：原版 `jpn_glyph.abc` 的 `mapping[cp]` 就是 **`rec32[]` 的下标本身（0-based）**，
索引 0 是一个**没被任何码位引用的孤儿字形**（原版 GlyphCount 2860 / mapping 值域 1..2858）。
我第一版按「索引从 1 开始」写 `mapping = i + 1`，但记录仍按 0-based 存放 ⇒ 每个字符都取到下一个字形。

正确做法（已在 `font-rebuild-jpn.fsx` 落地）：
1. 字形表**索引 0 放一个 1×1 透明占位**（`mapping = 0` 的码位显示空白）；
2. 实际字形从索引 1 开始；`mapping[cp] = i`（0-based 直接索引，不再 +1）；
3. `GlyphCount = 实际字形数 + 1`。

修后校验：`GlyphCount=4230 / mapping 非零 1..4229 / 唯一 4229`，字母 P→glyph 49、
Q→50、1→18，裁图确认字形正是 P/Q/1 ✅。

**另一处同时修的**：字形行内间隔 **1px → 2px**。第一版装机后深色背景下
`能`、`我` 等字左边有 1px 细线（相邻字形边缘串色），加大间隔即消除。

**(a) 黑字**：Indexed8 无论怎么配调色板都渲染成黑色 ⇒ 强烈怀疑

笔画少的字被放大、笔画多的保持，视觉上字号就乱了。
⇒ 正确做法是**统一字号渲染**（照 `font-rebuild.fsx` 的 `calibrate()`：让「漢」bbox 高 = 目标值，
所有字共用同一字号与同一绘制原点），而不是逐字拉满格子。
