## 总结论（2026-10-18）

**A/B/C/D 全部 PASS，汉化技术路线全部实机成立**：

- ADV 对话 = pac 内嵌字库，位图可改、字形可追加（中文按 Unicode 码位直接映射，无需 exe patch）；
- 台词图（TGA type9）重制路线成立；
- 现役图像 UI（按钮/角色名/存档/开场图）HIP 重制路线成立；
- 菜单/日期卡文字为实时渲染（Font00/GDI）——走 Font00.abc 解析路线；
- 硬约束：jpn_glyph.hip < 3.6MB、jpn_glyph.abc < 600KB（装载缓冲断言）。

> 「ruby 位移出框外」判定为**游戏原生显示行为**（我们重编码的图片与原版逐像素一致，
> ruby 本就在画布顶部，游戏字幕框比画布矮导致顶部裁切），与补丁无关。

## 进游戏看什么

启动游戏 → **开场（00_0-01 章，游戏最开头）**：

1. **测试 C**：开场白第 1 幕中央大字字幕应带**品红边框和品红大 X**（原图「影を生み出す月灯り」描边字）。
   - 品红框/X 出现 → C PASS（游戏读到了我们重编码的 TGA）。
   - 字幕消失/花屏/游戏崩 → C FAIL（TGA 编码器产物不被接受，记录现象）。
2. **测试 A**：开场白配音台词起（第 5 句「こちら二班！」及之后），**所有「こ」变成品红实心方块**。
   - 出现品红方块 → A PASS（坐实 ADV 用 pac 内嵌字库 + 位图修改即时生效）。
   - こ 照常显示 → A FAIL（对话字体不走内嵌字库，逆向结论需修正）。
3. **测试 B**：同一句应显示为「こちら二班！**[品红方块]**」——句尾的「汉」也是品红方块。
   - 句尾出现品红方块（位置、宽度正常，不挤行）→ B PASS（追加字形全链路通）。
   - 句尾空白/窄缝/整句不显示 → B FAIL（记录现象；追加记录的 32B 尾 16B 语义存疑，见 abc-hip-font.md §2）。
4. **测试 D**（最终版 v2）：开始游戏，出现**确认对话框**（「はい/いいえ」或「最初から/つづきから」
   按钮）时，「はい」/「最初から」高亮按钮应带**品红边框+对角线**。
   - 按钮带品红 → D PASS（GeoArcSys 重编码 HIP 被现役 UI 管线接受）。
   - 按钮消失/花屏 → D FAIL（记录现象）。

> 注意：开场白第 1–4 句是预渲染图（大字模式不查 atf），第 5 句起才走 atf+字库实时渲染，
> 所以 A/B 要看第 5 句之后。

```powershell
Copy-Item "$bk\AE\title\UI_02_title.pac"      "$game\AE\title\" -Force
```
